# Changelog
All notable changes to this crate will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

This crate versions and ships independently of the `frensense` binary. It owns
the grammar-facing language specs, the rule cards every reporting surface reads
its prose from, and the severity/CWE tables. The vocabulary *tables* that feed
sink and source matching are generated by `frensense-packgen`.

## [0.8.0] - 2026-10-30

### Breaking
- **`NodeRole` gains a variant and its later discriminants shift.**
  `NodeRole::KeywordArgument` (spec.rs:129) is new, inserted before `ClassDef`,
  so every variant from `ClassDef` (25) through `Other` (32) now has a
  discriminant one higher than in `0.7.0`; `NodeRole` is also exhaustive. Both
  are breaking for downstream code that casts a variant to a number or matches
  the enum without a wildcard. `Export` gains `visibility` and `kind` fields.
  `cargo semver-checks check-release --release-type patch` against the published
  `0.7.0` reports 3 major checks failing for exactly these items.

### Added
- **Advisory CWE classification**: built-in advisories now carry their canonical
  CWE so findings resolve to a stable CWE identifier instead of a generic label.
- **Rule cards** (`rule_card` module): one card per sink label and built-in
  checker rule holds the stable id, title, CWE list, why and fix, and the
  severity tables resolve through them (`card_by_id`, `checker_key`,
  `cwe_url`, `all_cards`), so no built-in rule can ship without a CWE and the
  terminal, SARIF, JSON and `frensense explain` surfaces cannot drift. Tests
  enforce unique ids, a CWE on every card, and that only fallback cards are
  generic. `frensense` reports the text; this crate owns it.
- **`NodeRole::KeywordArgument`**: keyword arguments (`f(x=1)`, `obj.f(a: 1)`)
  get their own role instead of falling through to `Other`/`Argument`, so a
  spec can classify them as a slot without a node-kind string.
- **CWE-94 tagging for Code Execution**: `eval`, `exec`, and `compile` sinks now
  carry CWE-94 (Code Injection). The mapping previously matched a dead arm - the
  sink slug is `"execution"`, not `"eval"` - so Code Execution findings were
  reported without a resolvable CWE. CWE-94 class TPR moves from 0% to 35%.
- **CWE-601 tagging for Open Redirect**: `redirect`-labelled Resource-role sinks
  now carry CWE-601 (URL Redirection to Untrusted Site). CWE-601 class TPR moves
  from 0% to 61.5%.

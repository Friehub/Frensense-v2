# Frensense v2: the first preview

v1 taught us an important lesson: pattern-shaped detection plateaus quickly.
Every new framework needed another rule, every rule brought false positives,
and the rules could not reason about *how* data moves.

So v2 is a **compiler first, checker second**. Every file is lowered to a
lightweight IR; the engine builds def-use chains, a call graph,
Steensgaard points-to, a heap model with memory SSA, and an SVFG.
A finding is an exact reachability query on that graph, with the concrete
source-to-sink path attached.

## What's in 0.7.1-preview.1

- **Memory safety**: use-after-free, double-free (with interprocedural
  allocation/deallocation wrapper summaries), and out-of-bounds checkers.
- **Value-aware guards**: an abstract-interpretation value lattice with
  branch sharpening, inside `if i < arr.len()`, the engine *knows* the
  bound holds, so range guards are proven, not pattern-matched.
- **A corpus that teaches**: label a vulnerable example and its fixed twin,
  and the bundler learns source/sink/sanitizer facts *and* policies into a
  checksummed `.frc` bundle. Facts must replay-verify before they ship.
- **Agent surface**: MCP (audit, scan-file, diff), LSP diagnostics, GitHub
  Actions annotations, and stable finding IDs.

## Where v1 went

The v1 documentation is preserved at [/v1/](/v1/). We kept it online on
purpose: it documents what the first attempt could and could not do, and the
[gap analysis](https://github.com/Friehub/Frensense) that motivated the
rebuild. v2's architecture chapters are the answer to those gaps.

## What's next

The corpus is the roadmap now. Next milestones: a relational/octagon value
domain (B2), heap model v2 for prototype-pollution flows, and per-framework
`.frc` bundles starting with Next.js.

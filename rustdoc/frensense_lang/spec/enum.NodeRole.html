Expand description

What role does a tree-sitter node play in the language?

Variants carry the field names needed to walk child nodes so callers never need a second lookup. All *_field values are Cow<'static, str>: Borrowed for spec vocabulary (tree-sitter grammar constants, no allocation), Owned for bundle-learned roles (allocated once per fact, never leaked).

Variants§

§

Function

A named or anonymous function / method / closure.

Fields

§is_method: bool

True when the grammar distinguishes methods from top-level functions (TS method_definition, Go method_declaration).

§name_field: Option<Cow<'static, str>>

Field holding the function’s name identifier, if any. None for arrow functions, lambdas, anonymous closures.

§params_field: Cow<'static, str>

Field holding the parameter list node.

§body_field: Cow<'static, str>

Field holding the body block node.

§

Declaration

A variable declaration with an initializer: let x = expr (JS/Rust), x := expr (Go), and Python’s x = expr, which has no separate declaration form.

Fields

§name_field: Cow<'static, str>

Field holding the declared name (or binding pattern).

§value_field: Cow<'static, str>

Field holding the initializer expression.

§

Assignment

A mutation of an existing binding (x = expr, x += expr).

Only the grammars that spell mutation as its own node kind use this; Python’s plain x = expr is a NodeRole::Declaration.

Fields

§lhs_field: Cow<'static, str>

Field holding the assigned target.

§rhs_field: Cow<'static, str>

Field holding the assigned value expression.

§

Call

Any function / method invocation.

Fields

§callee_field: Cow<'static, str>

Field holding the callee expression.

§args_field: Cow<'static, str>

Field holding the argument list node.

§

MemberAccess

Member / field access producing a value (not a call). obj.field, obj->field, obj.attribute.

Fields

§object_field: Cow<'static, str>

Field holding the accessed object.

§property_field: Cow<'static, str>

Field holding the accessed property name.

§

Branch

An if / else if / else chain, or a C-style switch_statement.

Grammars whose switch/match dispatches on one subject are NodeRole::Match instead, and a ternary expression is NodeRole::Conditional.

§

Conditional

Ternary conditional EXPRESSION (a ? b : c, Python a if c else b). Separate from Branch: both arms are expressions producing a value, lowered as branch + Phi, not as a statement-level fork.

§

Loop

A loop (for, while, do, loop): the CFG adds a back-edge.

§

Return

A return statement or expression.

§

Try

A try block: the exception edge starts here.

§

Catch

An exception handler (catch clause, Python except clause).

§

Finally

A finally block.

§

Throw

A throw statement or expression (Python raise).

§

ErrorGuard

Go: if err != nil { return … } - structurally a Branch but semantically an error propagation guard; the engine needs to detect it for auth-guard dominator analysis.

§

ContextManager

Python: with expr as var: - a context-manager entry; the callee may be a path/file sink.

§

ErrorPropagation

Rust: the ? postfix operator - propagates errors, terminates the current scope if the value is Err.

§

Await

An await expression (JS/TS, Python, Rust) or Go’s defer / go statement, whose work runs outside the current evaluation.

§

Block

A block of statements ({ … }, an indented block).

§

Composite

Value-context composite literal: JS/TS object used as a value (not a statement block), array, object_pattern in expression position. Uniformly-keyed objects and arrays lower to an allocation with one store per property/element: field reads resolve through field-sensitive heap edges (taint in one property does not pollute reads of another), while whole-container consumers see every stored value. Objects with unkeyed children (spreads) keep the legacy may-analysis union - conservative for taint.

§

Import

An import declaration or call: import, use, require.

§

Export

An export declaration (JS/TS only).

§

Identifier

A bare name reference.

§

Literal

A literal value: string, number, boolean or null.

§

Parameters

A parameter list (formal_parameters in JS/TS, parameters in Python, parameter_list in Go/C) or one parameter node a grammar spells on its own (parameter, parameter_declaration, typed_parameter, default_parameter, positional_separator, …).

§

Arguments

An argument list: arguments (JS/TS/Rust), argument_list (Python/Go/C), Python’s generator_expression, or a Rust macro’s token_tree.

§

KeywordArgument

A named call argument (f(secure=False)): Python keyword_argument. Distinct from a plain expression so the IR can keep the argument’s name alongside its value - a policy that constrains one flag cannot be expressed correctly by position when the caller may omit earlier optional arguments.

Fields

§name_field: Cow<'static, str>

Field holding the argument name.

§value_field: Cow<'static, str>

Field holding the argument value expression.

§

ClassDef

Class / struct / enum / interface / trait definition.

§

BinaryOp

Binary expression: a + b, x && y.

§

UnaryOp

Unary expression: !x, -x, *ptr.

§

Match

Pattern match: match (Rust), switch as type/value switch (Go), match statement (Python), switch_expression (JS/TS).

§

Unsafe

Rust: unsafe { … } block.

§

AsyncBlock

An async block (async { … } in Rust, Python async_block).

A JS/TS async function / Python async def is still a NodeRole::Function: only a block without a function of its own gets this role.

§

Other

Anything the engine does not need to inspect.

Expand description

Everything the frensense engine needs to know about one source language.

Implement this once per language. The engine never matches raw node-kind strings anywhere else.

§Object safety

The trait is object-safe: it can be stored as Arc<dyn LanguageSpec> in the LanguageRegistry.

fn classify(&self, kind: &str) -> NodeRole

Classify a tree-sitter node kind into a NodeRole.

This is the single hot-path entry point for all engine subsystems. The returned variant carries the field names needed by the caller so no second lookup is required.

ⓘ
match spec.classify(node.kind()) {
    NodeRole::Call { callee_field, args_field } => {
        let callee = node.child_by_field_name(callee_field);
        // …
    }
    NodeRole::Assignment { lhs_field, rhs_field } => { /* … */ }
    _ => {}
}

fn preprocess<'a>(&self, source: &'a str) -> Cow<'a, str>

Rewrites the source into something the grammar can parse, run immediately before lowering. The default is the identity: the source is parsed as-is.

Position contract: the rewrite MUST preserve every byte offset — same total length, same newline layout — so tree-sitter nodes and every line/column derived from them still point at the original file. Single-file-container formats (Vue SFCs, and later Svelte or Astro) use this to blank template markup into same-length runs of spaces instead of extracting script text to a separate buffer.

Source

fn fact_language(&self) -> &'static str

The language key the FactTable and learned bundles key this spec’s knowledge under. Defaults to name; a container format delegating to another spec’s grammar also delegates its vocabulary (a Vue SFC’s script is TypeScript, so its facts live in the typescript section). Registry identity still uses name().

fn ternary_cond_index(&self) -> usize

Index of the condition among a ternary expression’s named children.

JS/TS a ? b : c → [cond, then, else], condition at 0. Python then if cond else else_arm → [then, cond, else], condition at 1 (middle). Defaults to 0.

Source

fn is_property_kind(&self, kind: &str) -> bool

Is this node kind a property-name (a named field access) rather than a computed index?

Used by the lowering to distinguish obj.field (LoadField, the name matters for member-path source matching and sink method resolution) from obj[expr] (LoadElement). The default heuristic recognizes the common JS/TS kinds; languages whose attribute/selector property nodes have different grammar kinds MUST override this:

  • Python attribute: the property child is a plain identifier
  • Go selector_expression / Rust field_expression: field_identifier

A wrong answer silently turns method calls into CallPointer sites and loses sink matching entirely.

fn is_function_node(&self, kind: &str) -> bool

Returns true if this node is the entry node for a function definition.

Convenience wrapper around classify; the default implementation delegates. Override only when a language has edge-cases (e.g. Python decorated_definition which wraps the real function_definition).

fn decorator_guard_calls<'a>( &self, node: Node<'a>, source: &'a str, ) -> Vec<&'a str>

Decorator / attribute call names applied to this function-definition node (@guard(...), #[guard], @app.route(...)).

Pure grammar mechanism: decorators are placed either as direct children of the definition (Python decorated_definition, JS/TS member decorators) or as preceding sibling attribute nodes (Rust #[attr] on fn). Their text reliably starts with @ or #[, so placement and spelling are recognized structurally and no per-language node-kind table is needed. The name is stripped to its last . segment and cut at the call paren so @group.require_role(user) yields require_role.

fn is_object_composite(&self, _kind: &str) -> bool

A composite literal that is keyed ({ a: 1 }) rather than positional.

The lowering allocates a keyed composite as an object and stores each entry under its field, keeping reads field-sensitive; one that is neither keyed nor positional (a parenthesized expression, a grammar’s own composite wrapper) keeps the conservative union lowering. Answering true here for such a shape would silently make it field-sensitive.

fn for_loop_iterable<'t>(&self, _node: Node<'t>) -> Option<(Node<'t>, Node<'t>)>

fn function_params<'t>(&self, fn_node: Node<'t>) -> Option<Node<'t>>

The parameter-list node of a function definition, when the grammar exposes one.

Follows the NodeRole::Function’s params_field, and keeps walking while the node it lands on is not a NodeRole::Parameters list. C needs that: its function_definition exposes declarator, and the list sits one hop further, inside function_declarator’s parameters field (pointer_declarator may wrap it again). Handling the hop here means no consumer carries a C-specific walk.

Source

fn function_name_node<'t>(&self, fn_node: Node<'t>) -> Option<Node<'t>>

The node that names a function definition.

Follows the NodeRole::Function’s name_field until it reaches an NodeRole::Identifier. A grammar that names the function inside a declarator chain (C: function_definition → declarator → function_declarator → identifier, with pointer_declarator in between for void *f(void)) says so by exposing that chain in name_field, so no consumer walks it.

None for a function that binds no name (arrow function, lambda, closure, and a Python decorated_definition, whose name belongs to the wrapped definition).

Source

fn is_self_parameter(&self, _kind: &str) -> bool

A parameter that binds the receiver of a method (&self, &mut self). Its name is the language keyword, not its text.

Source

fn param_bindings<'t>(&self, param: Node<'t>) -> Vec<Node<'t>>

The binding identifiers of one parameter node, in declaration order.

Grammars disagree about how many names one parameter node carries and where they sit, so this is the one place that knows:

  • JS/TS: required_parameter/optional_parameter with a pattern field, and ...rest as a rest_pattern around the name.
  • Python: a plain identifier, plus the annotated/defaulted wrappers (x: T, x=v, x: T = v) and the splats (*x, **x).
  • Rust: a parameter node wrapping the name identifier.
  • C: parameter_declaration shaped type declarator, where the declarator may be pointer_declarator → identifier (char *p).
  • Go: parameter_declaration/variadic_parameter_declaration shaped name ... type, with one name field per grouped name (a, b string is a single declaration and binds both names).
Source

fn is_error_guard<'tree>(&self, _node: Node<'tree>, _source: &str) -> bool

Returns true when this node is a Go-style error guard: if err != nil { return … }.

The default always returns false. Override in the Go provider.

fn context_manager_call<'s>( &self, _node: Node<'_>, _source: &'s str, ) -> Option<&'s str>

For Python with_statement nodes, return the text of the call inside the as clause if it looks like a file/resource sink.

Returns None for all languages that don’t have context managers.

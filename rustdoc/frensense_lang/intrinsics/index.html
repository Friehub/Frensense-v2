Method names the languages’ own builtin types carry.

This is language mechanism, not detection knowledge: it says “this name belongs to the language’s containers, sequences and file handles”, never “this call is dangerous”. That is the line between this crate and frensense-packgen (which owns sink / source / sanitizer vocabulary): neither the engine nor the pack may carry it.

§Why the engine needs it

When a call’s receiver type cannot be resolved (m.get(k), buf.write(s), items.append(v)), the call graph must not bind the site to a program function that merely shares the bare method name. A local fn get() is not Map.prototype.get, and the fabricated interprocedural edge drags unrelated same-named functions into the taint walk - the dominant false-positive class in the real-repo audit (tests/mre). A name in this table is known to belong to a builtin type, so the site stays external.

§This is not a denylist of dangerous calls

Membership carries no severity, CWE or label. A taint flow that reaches send through a resolved receiver is still reported; only the unresolved receiver’s bare-name binding is refused.

§Extending the table

Add a name only when the language’s standard library defines it on a builtin type across the supported languages’ shared vocabulary (Map.get, dict.get, Vec::get, sync.Map aside). A name that is only ever a user-defined method belongs in a corpus bundle, not here.

Expand description

One family’s variants, lowered once. The gate re-scans families per candidate fact; without pre-lowering the gate is O(candidates x families) lowerings and times out at corpus scale.

Lowering runs under the family’s own seeded tables (spec + default pack) so the gate lowers with exactly the pack vocabulary the CLI scan lowers with (route-registration patterns since Phase 6.4, dynamic grammar facts once a family teaches them) - gate and CLI lowering can never diverge on pack vocabulary.

pub fn downstream_echo( &self, config: &TaintConfig, facts: &FactTable, call: &str, siblings: &BTreeSet<String>, ) -> Option<String>

The candidate sink this call’s tainted argument flows through, if any.

A positive can taint more than one call: the defect, and calls that merely receive its result (the response writer that echoes a query’s rows, the logger that prints a deserialized document). Separation cannot tell them apart - the negative validated the value upstream, so every downstream echo is silent there too, and both candidates pass. Learning the echo publishes a sink that fires on any tainted value of that shape, which is exactly the false positive the corpus review found (JsonResponse, annotate, list taught by the Django Trunc family).

The captured source→sink path answers it directly: a call whose argument path already names another candidate sink is downstream of it, so the upstream candidate is the one carrying the family’s knowledge.

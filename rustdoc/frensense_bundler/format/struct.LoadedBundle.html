pub fn withheld_sanitizers(&self) -> usize

How many sanitizer facts this bundle carries that its trust tier does not let it apply.

A bundle built before class scopes existed (v7) carries sanitizers with no scope, and a custom bundle may not ship them at all. They are withheld, which keeps findings visible, but a user whose false positives came back needs to be told why.

Source

pub fn withheld_sanitizers_notice(&self) -> Option<String>

One-line explanation for Self::withheld_sanitizers, or None when nothing is withheld.

Source

pub fn effective_learned_facts(&self) -> Vec<LearnedFactEntry>

The facts this bundle’s trust tier actually permits it to ship.

Custom bundles are additive-only: sinks, sources and policies, no sanitizers. Community bundles may ship a sanitizer only when it is both class-scoped and name-scoped (package/receiver). Certified bundles ship everything. This is the single filtering point every consumer must use; reading learned_facts directly would re-open the cross-class blind spot the tier exists to close.

Source

pub fn effective_sanitizer_scopes(&self) -> Vec<&SanitizerScope>

The sanitizer class scopes this bundle’s trust tier permits it to ship.

One entry per sanitizer fact that survived Self::effective_learned_facts. A consumer installs the fact from the entry list, then applies the scope with frensense_engine::analysis::taint::facts::FactTable::scope_sanitizer.

Source

pub fn policy_tier(&self, rule: &str) -> Option<&str>

Reporting tier this bundle declares for rule, already capped by the bundle’s trust tier. None means the consumer’s rule registry decides (a certified bundle declared nothing).

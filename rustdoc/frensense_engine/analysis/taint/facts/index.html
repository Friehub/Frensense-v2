Expand description

Task 4.3 completion: sink signatures, per-API argument-position facts.

A blanket “every argument of a sink is dangerous” model causes the largest FP class in the e2e report: pool.query(sql, [email]) (parameterized, safe) alerts because the tainted value sits in arg 1, the safe channel.

A SinkSignature fixes this without engine surgery: it lists which argument slots of a named call are dangerous, and whether a binding parameter array (the parameterized-query safe channel) must be absent for the call to be dangerous.

Signatures come from the fact tables (frensense-lang built-ins merged with bundler-extracted learned facts via a FactTable). The engine only consumes them; updating a framework never touches engine code.

Expand description

The merged fact table: built-in language tables + bundle-learned facts.

Built from a TaintConfig (name sets, backward compatible) plus optional signatures/sanitizer facts supplied by frensense-lang specs or a .frc bundle.

Fields§

§sink_signatures: FxHashMap<String, SinkSignature>

By call name. Absent = default “all args dangerous” for configured sinks.

§lang_sink_signatures: FxHashMap<String, FxHashMap<String, SinkSignature>>

Language-keyed sink signatures: language -> call -> signature.

The default pack declares its provider vocabulary per language, and a bare call name is not portable between them: Rust’s File::create and a JavaScript prisma.order.create(...) share the last segment create, so installing both into one name-keyed map makes the Rust fact fire on the TypeScript call. Measured on a real repo: a single .rs file in a TypeScript-only package took the scan from 6 findings to 40, all of them create/output calls in .ts files.

Facts therefore stay under the language that declared them, and matching consults the call site’s language first (FactTable::sink_signature_for_language). sink_signatures keeps only genuinely language-agnostic knowledge ("*" pack group, bundle facts, hand-built configs).

§lang_sources: FxHashMap<String, FxHashSet<String>>

Language-keyed taint sources: language -> patterns.

The source mirror of lang_sink_signatures: conventional parameter names (req, input, …) and framework source patterns are declared per language, so a JavaScript-only name must not seed taint in a Rust file. input is a request source in TypeScript and an unrelated local in Rust; sharing one set made info!(..) a source for every Rust tokio::spawn call in the same repo.

Dedup on (rule, when_call) at merge time, provenance-ordered per entry.

§prepared_statement_prefixes: FxHashSet<String>

Lowercase name prefixes of calls that create a bound-parameter statement handle (Prepare, prepareStatement, prepare_cached).

A handle from one of these factories executes text that was fixed when it was created, so the arguments of its later calls are bindings, not SQL. Which factory names exist is pack knowledge; the engine only walks the def chain and matches the prefix against this set.

§weak_hash_disclaimer_tokens: FxHashSet<String>

Argument tokens (lowercase) that disclaim security use of a weak digest: a literal false flag in a non-payload position marks the digest as a checksum or cache key, not as credential protection. Pack knowledge; the engine only decides which positions are flags.

§weak_hash_rules: Vec<WeakPrimitiveRule>

Weak-hash policy rules (default-pack-seeded).

§integer_overflow_rules: Vec<(IntegerOverflowRule, Provenance)>

Corpus-extendable allocation-size overflow rules (CWE-190 -> CWE-680; default-pack-seeded, bundle extension via LearnedFactEntry::IntegerOverflowRule from a family’s [frensense] check-rule: declaration).

§insecure_config_selectors: Vec<InsecureConfigRule>

Insecure config selectors (default-pack-seeded).

§key_size_rules: Vec<KeySizeRule>

Key-size policy rules (default-pack-seeded).

§suspicious_hash_wrappers: FxHashSet<String>

Suspicious hash-wrapper names (default-pack-seeded).

§verb_sinks: FxHashSet<String>

Last segments that come ONLY from dotted client sinks (got.get, axios.post, …). These verbs are ambiguous, Map.get, router app.post, LRU .put all share the names, so they match receiver-aware: the call only counts as a sink when the receiver’s root is a known client (see Self::client_roots).

§client_roots: FxHashSet<String>

Receiver roots that make verb_sinks real client calls, derived from the first segment of dotted verb sinks (got, axios, http).

§receiver_roles: FxHashMap<(String, String), SinkRole>

Receiver-specific roles for dotted sinks that share their last segment with a different-role bare entry: (receiver_root, method) -> role.

Example: KVNamespace.put is StorageWrite while bare run is SqlInjection; shell.run is CommandInjection. When the engine sees kv.put(...) and the receiver root resolves to kv’s declared dotted root, THIS role wins over the bare entry’s, the receiver is the disambiguator, exactly like verb_sinks for match/no-match.

§receiver_labels: FxHashMap<(String, String), String>

Receiver-specific label slugs: (receiver_root, method) -> label slug.

§receiver_qualified_sinks: FxHashMap<String, FxHashSet<String>>

Last segments that are ONLY sinks under a declared receiver root: last -> declared roots.

A dotted declaration (pickle.loads, urllib.request.urlopen) publishes a bare shadow of its last segment, because the walker matches a virtual call by method name and cannot see the module the method was reached through. Without this map the shadow is receiver-agnostic: json.loads(t) inherited unsafe-deserialization semantics from pickle.loads, and client.urlopen(t) inherited SSRF from urllib.request.urlopen.

The map turns “declared qualified” into an engine-enforced requirement: a name listed in this map arms only under a receiver root (or an import origin) the declaration named. The engine stays mechanism-only - which roots qualify which name is pack/bundle knowledge, not engine vocabulary.

§bare_sink_names: FxHashSet<String>

Last segments declared BARE (a declaration with no dot in it).

A bare declaration is the receiver-agnostic form: it is the language builtin’s own name (eval, exec, open). A name that is only ever declared qualified is gated by receiver_qualified_sinks; a name declared bare is not - it keeps matching any receiver, which is correct for a builtin and wrong for a library function.

§session_roots: FxHashSet<String>

Receiver roots of trusted session stores (authenticatedUsers): store.get(token) returns a server-issued session object or undefined, values read off the result are not attacker-controlled (the pack ships these with session-trust sanitizer facts).

§learned_sources: FxHashSet<String>

Taint-source patterns learned from a .frc bundle: call names or member-access paths whose results carry attacker-controlled data. Merged into the scan’s TaintConfig::sources before analysis so bundles teach new frameworks without touching the built-in tables.

§grammar_roles: FxHashMap<(String, String), TeachableNodeRole>

Dynamic node role classifications learned from a .frc bundle: (language, node_kind) -> role. Stored as the owned TeachableNodeRole (bundle payload type) and converted to a frensense_lang::NodeRole on lookup, so applying a fact never allocates 'static memory (the previous Box::leak intern leaked per merge, growing unboundedly in long-lived MCP/LSP processes).

§grammar_features: FxHashMap<(String, String), FxHashSet<GrammarFeature>>

Dynamic grammar features learned from a .frc bundle: (language, node_kind) -> Set<GrammarFeature>.

§custom_allocators: FxHashSet<String>

Dynamic custom memory allocators learned from a bundle or specification.

§custom_deallocators: FxHashSet<String>

Dynamic custom memory deallocators learned from a bundle or specification.

§memory_functions: Vec<MemoryFuncSpec>

Memory-function vocabulary (allocators/deallocators and their capacity contracts), default-pack-seeded (Phase 6.1). Empty means the caller built a bare table; the checks then see no memory vocabulary at all.

§buffer_builtins: Vec<BufferBuiltinSpec>

Buffer-manipulation vocabulary (copy/fill/read builtins with their dst/src/len argument slots), default-pack-seeded (Phase 6.1). Empty means the caller built a bare table; the OOB check then sees no buffer vocabulary.

§stack_allocators: Vec<String>

Stack-frame allocators (alloca, …), default-pack-seeded (Phase 6.5); leak-style checkers exclude them.

§route_patterns: FxHashMap<String, Vec<String>>

Route-registration call patterns per language ((language or "*", patterns)), default-pack-seeded (Phase 6.2); the lowering harness unions these with the spec’s route verbs.

§collection_constructors: FxHashSet<String>

Collection constructors (Set, Map), default-pack-seeded (Phase 6.5); the allowlist-definition check reads their literal elements.

§schema_describe_methods: FxHashSet<String>

Schema-describing methods (describe, description), default-pack-seeded (Phase 6.5).

§null_tokens: FxHashSet<String>

String literals that compare as the null pointer (NULL), default-pack-seeded (Phase 6.5).

§session_accessors: FxHashSet<String>

Read-accessor method names of trusted session stores (get), default-pack-seeded (Phase 6.5).

§receiver_params: FxHashSet<String>

Formal parameter names receiving the implicit receiver (self, this), default-pack-seeded (Phase 6.5).

§idor_keys: FxHashSet<String>

Dynamic IDOR-class query keys learned from a bundle or specification.

§idor_finder_sinks: FxHashSet<String>

Dynamic IDOR-class finder sinks learned from a bundle or specification.

§propagators: FxHashMap<String, Vec<usize>>

Dynamic taint propagators: call -> input_arg_slots.

§propagator_blocks_receiver: FxHashMap<String, bool>

Per-call receiver-taint declarations from propagator rules: call -> blocked, where blocked is !tainted_receiver. A key is present only when a rule explicitly named it; unknown calls keep the default receiver pass-through. Stored as a two-way map (not a negative set) so a later tainted_receiver: true entry can un-block a key an earlier tainted_receiver: false entry blocked - keeping install and merge last-wins for both the arg slots and this flag.

§guard_denylist_patterns: Vec<String>

Guard denylist string patterns: default-pack-seeded (GuardDenylistPattern, Phase 6.5) and bundle-learned (GuardDenylistPattern).

§max_complexity: Option<usize>

Optional cyclomatic complexity limit override for FunctionComplexity check. When None, defaults to health::MAX_COMPLEXITY (25).

pub fn sink_signature(&self, call: &str) -> Option<&SinkSignature>

Signature for a sink call, without a call site’s language context; None if the call is not a declared sink in any language.

This is the “no call site” accessor (bundler candidate checks, table assertions): it takes the language-agnostic lane, then over- approximates across every installed language. The scan path always has an IR and must use Self::sink_signature_for_language with its language instead, or a Rust fact would arm a TypeScript call.

pub fn add_class_scoped_sanitizer( &mut self, fact: SanitizerFact, classes: &[String], )

Install fact as a sanitizer proven to defeat only the given sink classes (bug_classes.json ids such as inj.sql; * is a wildcard).

The class scope rides on the published FactTable::scoped_sanitizer_facts map under the reserved CLASS_SCOPED_SANITIZER_PREFIX key, so the table keeps its shape: one entry (class:<id>, call) per class. An empty classes list is a plain, unscoped install.

Source

pub fn scope_sanitizer( &mut self, call: &str, package: Option<&str>, classes: &[String], ) -> bool

Re-scope an already-installed sanitizer fact to classes.

The fact is moved out of the unscoped/package-scoped slot and re-installed under the class keys of Self::add_class_scoped_sanitizer. Returns false when no fact is installed for (package, call).

pub fn sanitizer_classes( &self, call: &str, origin_package: Option<&str>, ) -> Vec<String>

The sink classes call was proven to defeat for origin_package.

Empty means the fact is unscoped (valid for every class, the legacy reading). A package-qualified class scope follows the same recall-safe rule as FactTable::sanitizer_fact_scoped (crate-internal): it only fires once import resolution confirms its package.

pub fn sanitizer_fact(&self, call: &str) -> Option<&SanitizerFact>

Sanitizer fact for a call; None if not a sanitizer.

No import origin is available at this call site, so package- scoped facts are inert here (recall-safe: they only ever suppress under a confirmed origin). Pass Some(origin) via Self::sanitizer_fact_scoped where import context exists.

pub fn sink_signature_for_language( &self, call: &str, language: Option<&str>, ) -> Option<&SinkSignature>

Sink signature for call in the language it was written in.

Precedence: the language-agnostic lane first (a consumer bundle and the "*" pack group are the last seeding layer, so they win over a language section), then the call site’s own language - except that a blanket all-args placeholder (SinkSignature::is_blanket, what TaintConfig::sinks seeds for every configured name) never shadows the language’s own entry, which knows the call’s dangerous slots and identity-payload keys. A qualified callee (std::fs::read_to_string) also matches shorter declared shapes through its :: suffixes, exact matches first - the same rule FactTable::sink_signature applies.

language: None is the legacy “no call-site context” form: it over-approximates across every installed language, which is why the real scan path always passes the IR’s language.

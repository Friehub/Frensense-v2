Fact-vocabulary fingerprint: the wire compatibility contract for .frc bundles.

A bundle stores LearnedFactEntry values and HintKind discriminants by position (bincode is positional and non-self-describing). An older binary therefore cannot decode a bundle that uses a variant added after it was built, and the failure surfaces as an opaque decode error deep inside serde rather than as a version mismatch a user can act on.

This module replaces that silence with one number. It hashes the ordered serialization surface - hint kinds and fact-entry variants - with a stable FNV-1a so it is reproducible from source without a runtime dependency. A bundle records the fingerprint it was built against; the engine compares it at load time and refuses, by name, to decode vocabulary it does not know ([frensense-bundler’s header check]).

The ratchet is mechanical, not honour-based:

  • HintKind::index and LearnedFactEntry::wire_index are exhaustive matches, so adding a variant is a compile error that lands the developer next to the vocabulary lists.
  • tests::vocabulary_lists_are_ratcheted fails until the new variant is appended to HintKind::ALL / LearnedFactEntry::VARIANT_TAGS, and tests::vocabulary_fingerprint_is_committed fails until the change is acknowledged by updating FACT_VOCABULARY_FINGERPRINT - which is also the cue to bump BUNDLE_VERSION and regenerate the default pack.

Struct field additions are not covered here (they are caught by the bundler’s committed golden bundle, which stops decoding once the layout moves); this fingerprint covers enum order and naming.

5//! `frensense-lsp` — Language Server Protocol adapter.
6//!
7//! Delivery, not analysis. The server reuses the per-file scan path
8//! (`Engine::run(file)`, the same path the CLI watch mode and the MCP
9//! tools use) and maps advisories onto LSP `publishDiagnostics`
10//! notifications on open/save. No `tower-lsp` dependency: the protocol
11//! subset an editor needs for diagnostics is small (three lifecycle
12//! methods, two document events, Base-64-free `Content-Length` framing),
13//! and hand-rolling keeps the dependency tree at zero while every
14//! interesting decision (severity mapping, stable IDs, URI handling)
15//! stays testable as plain functions.
16//!
17//! Behavior:
18//! - `initialize` advertises `textDocumentSync` (full sync, change=1)
19//!   and nothing else — diagnostics-only servers should not claim
20//!   hover/completion they can't serve.
21//! - `textDocument/didOpen` and `didSave` scan the file on disk and
22//!   publish one diagnostics array per version. Full sync: the client
23//!   sends the whole document, but scanning the saved disk state keeps
24//!   the engine the single source of truth (no in-memory AST fork).
25//! - Diagnostics carry the stable finding ID in `code` and the
26//!   observation in `message`, so editor inline display and the CLI
27//!   refer to the same bug the same way.
28//! - `didClose` clears diagnostics for that file (protocol hygiene:
29//!   stale editor tabs must not show dead findings).
30

32pub mod server;

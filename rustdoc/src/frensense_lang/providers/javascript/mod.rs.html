4//! JavaScript and TypeScript [`LanguageSpec`](crate::spec::LanguageSpec)
5//! implementations.
6//!
7//! JavaScript, TypeScript and a Vue SFC's script blocks are one language
8//! family: same AST grammar (TypeScript is a superset of JavaScript in
9//! tree-sitter-typescript), same classification, same imports and exports.
10//! The family's [`LanguageSpec`](crate::spec::LanguageSpec) behaviour is
11//! therefore written **once** behind [`JsFamily`], and each member states only
12//! its [`JsDialect`] — the extensions, grammar, symbol query and wrapper that
13//! actually differ.
14//!
15//! Layout:
16//! - `family` - the one `LanguageSpec` implementation plus [`JsDialect`]
17//! - `ast` - shared AST classification (node → [`NodeRole`](crate::spec::NodeRole))
18//! - `imports` - ESM/CommonJS import extraction
19//! - `packages` - npm package → [`PackageCategory`](crate::spec::PackageCategory) knowledge
20//! - `params` - parameter → [`TaintOrigin`](crate::spec::TaintOrigin) classification
21//! - `spec_ts` / `spec_js` - the two family members ([`TypeScriptSpec`],
22//!   [`JavaScriptSpec`])
23//! - `spec_vue` - the Vue SFC member ([`VueSpec`]: template blanked in place by
24//!   its `preprocess`, script blocks parsed by the TSX grammar)
25//!
26//! Security vocabulary (sinks, sources, sanitizers, propagators, session
27//! roots, route patterns) lives in `frensense-packgen` since Phase 6.3;
28//! the specs here are mechanism-only.
29

33mod packages;

36mod spec_ts;

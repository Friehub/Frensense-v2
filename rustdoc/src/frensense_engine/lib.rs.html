5//! Frensense engine: the dataflow compiler.
6//!
7//! The pipeline: parse (via `frensense-lang` specs) → lower → SSA → SVFG →
8//! callgraph → demand-driven taint. Knowledge about sources, sinks, and
9//! sanitizers lives in `frensense-lang` specs and `.frc`-bundle fact
10//! tables, merged into a [`analysis::taint::config::TaintConfig`] +
11//! [`analysis::taint::facts::FactTable`] at scan time.
12//!
13//! Crate layout (strict layering, each layer only depends on the ones
14//! above it):
15//! * [`ir`], the compiler frontend: `FunctionIR`, lowering, Memory SSA.
16//!   Pure data; knows nothing about taint or checks.
17//! * [`graph`], program-graph construction: SVFG, callgraph, heap
18//!   points-to, serialization.
19//! * [`analysis`], the engines: demand-driven backward taint (with its
20//!   fact table and context sensitivity), the forward engine, summaries.
21//! * [`checks`], non-dataflow policy rules (weak crypto, insecure JWT
22//!   algorithms), one module per rule.
23//! * [`harness`], the ONE implementation of "source text → analyzed
24//!   program graph", shared by the scanner, e2e drivers, and the bundler.
25//! * [`scan`], the stable query API: files + config + facts → findings.
26

29/// The engine crate version as published. Bundles record this as
30/// `built_by_engine`; the compatibility decision itself is made on
31/// [`analysis::taint::facts::fact_vocabulary_fingerprint`], because the
32/// serialized vocabulary (not the crate number) is what decides whether a
33/// bundle can be decoded.
34pub const VERSION: &str = env!("CARGO_PKG_VERSION");
